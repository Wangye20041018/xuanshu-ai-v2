## 一、目标与原则

把玄枢（FlowyAIPC 改造）在 **7~9 天**内做完 11 项改造 + 后端联动，交付一套**完整可日常使用**的本地 AI 桌面助手。原则：

- UI 与后端一起做，完成即可用。
- 四方并行，产出统一落 `03_产出区`，中央负责集成/打包/部署/验收，杜绝"干了没落地"。
- 厂商云端彻底摘除；云端能力走老板自定义 API 面板；本地推理内嵌、主进程拉起。

1. 11 项改造逐项可见、可用；UI 与 Semi Design 风格一致。

3. 模型三档切换真实生效：纯本地走本地推理、纯云端走自定义 API、智能调用可路由；输入框可看见当前档位。
4. 专家页 agent 添加/停用/删除（二次确认）真实影响运行时；首页对话设计 agent 后自动出现在专家页/会话可调用。
5. 定时任务真实定时触发并执行动作，不依赖绑定特定 agent。
6. 记忆/知识 两块数据可用、可检索、可管理。
7. 微信/QQbot 连接真实可用，不强制绑定 agent。
8. 会议：无人数设定；转写模型本地可用；总结由玄枢主模型生成。
9. AI 视频：无登录墙；时长可自定义；云端未接入时相应功能置灰并有提示。
10. 设置：匿名数据项已删；token 页显示本地/云端真实用量；模型-网关页可接入模型文件/调参/随启动/硬件面板/网络检查修复/云端 API 面板【密钥安全存储、可连通性测试、可删除】；安全页健康检查+修复可用；关于页显示版本与作者；账户/更新已删。
11. 全局通网：软件不再报断网；本地功能全可用；外网仅用于老板自定义云端 API。
12. 图标已替换为老板指定图案（含圆角矩形元素），杀进程/托盘/桌面/标题栏一致生效。
13. 软件整体启动正常、可日常对话，本地推理与云端切换均可用；回归首页不破。

## 六、接口契约（中央维护，跨模块必读）

**1) 本地推理统一端点（会议总结/专家问答/主题无关）**
- 玄枢本地推理由主进程拉起 llama.cpp，对外暴露 OpenAI 兼容端点。运行时提供 `getLocalModelStatus()`（IPC）返回：是否就绪/模型名/端口/上下文/是否带视觉头。
- 当前已知的本地 provider：`local-qwen` baseUrl=`http://127.0.0.1:8082/v1`（以中央 M3 实际交付端口为准，契约更新会同步意见墙+本文件）。
- 前端调用约定：一律走主进程 IPC（`window.oss?.xxx` 现成桥）发起，不直接 fetch 裸 IP；具体 IPC 名以中央联调时发布为准。

**2) 云端 API 接入（豆包 UI ↔ 中央后端）**
- Provider 数据存 `flowyaipc-providers.json`，中央负责读写与密钥加密；豆包只做 UI 与调用 `主进程暴露的增删改查/连通性测试` IPC，禁止前端直接落密钥。
- 三档切换：`纯本地=local-qwen`、`纯云端=用户云 provider（default 云）`、`智能调用=本地优先失败/超限转云`，由中央在 provider 层实现路由，前端只传档位。

**3) token 用量统计（豆包 token 页 ↔ 中央后端）**
- 中央在主进程埋点记录每次本地(模型)与云端(用户 API)的调用 token 数（含流式 usage 汇总），写入 `AppData\FlowyAIPC\usage.json`；豆包 token 页通过 IPC `getUsageStats()` 拉取展示（今日/累计、本地/云端分列）。

**4) 会议总结（WorkBuddy ↔ 中央）**
- 转写文本由"会议页内置模型下载 + 本地转写"产出；总结调用本地推理端点（契约1），由主进程 IPC 统一中转。WorkBuddy 按契约1的 IPC 约定调用，中央保证端点就绪。

**5) 新文件/新 UI 页面的挂载**
- 成品 bundle 为单一 `index-D5I3iBTS.js`。多人同改此文件会冲突：**各任务文件已按"模块代码区"划分改动手写位置**，中央集成时做冲突仲裁。**任何方不得全文格式化该 bundle 或改写其文件头部，只能作定位式局部修改**。
